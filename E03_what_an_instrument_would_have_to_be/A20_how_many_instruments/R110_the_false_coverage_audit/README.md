## ⑤ 先验证工具,再审计

`data.csv`(长表)与 pivot 宽表两条路各算一次真实非缺失 n:**完全一致,0 处不符** ⇒ 可以审计。
**参考:这个库里「行数 ≥150 而真实 <60」的变量规模就是假覆盖的规模。**

## 结果

**引用过 SCCS 变量的轮次 = 17。**

| 阈 | 被标出 |
|---|---|
| 真实 n < 30 | **3 / 17 = 0.176** |
| 真实 n < 60 | 8 / 17 = 0.471 |

**被标出的三个**:`R059`(#528 那一轮)· `R070` · **`R110`(本轮自己 —— 正对照是我故意种进去的)**。
前两个都是同一个变量:**`SCCS960`「违反乱伦禁忌」(Frayser 1985),真实 n = 29。**

**✅ 正对照** 工具标出 `SCCS490=5` / `SCCS491=6`。
**✅ 负对照** 体罚四件套(真实 n = 145/140/147/142)**未被标出**。**两者分得开 ⇒ 工具没坏。**

## ⚠ 而这个标记是代理,不是判决 —— 所以我去查了

**工具标的是「轮次里提到过低 n 变量」,不是「那个变量承担了声明」。** 按 P6,它是**必读清单**。
逐条读源码:`SCCS960` 在两轮里都出现在**候选池**中(`A_` 七个态度候选 / `SEV7` 七个严厉度变量),
**而那两轮的头号数字走的是 `SCCS165`/`SCCS167`,真实 n = 97 / 91 —— 审计确认无恙。**

> **⇒ 页面上没有一条声明是假覆盖的受害者。**
> **但那两轮里凡涉及 `SCCS960` 的格子,真实 n ≤ 29,低于本项目自设的地板 30 ⇒ 一律记「判不了」。**

## P6 代理账

| | |
|---|---|
| **PROPERTY** | 某条声明建立在假覆盖之上 |
| **PROXY** | 该轮次提到的 SCCS 变量里有真实 n < 30 的 |
| **IMPLICATION** | **只有一个方向可靠**:未被标出 ⇒ 该轮没有低 n 变量(可靠)。反过来**不成立** —— 被标出**不**证明声明依赖它 |
| **SAFE SIDE** | **只报「有低 n 变量在场」,从不判「这条声明坏了」** |

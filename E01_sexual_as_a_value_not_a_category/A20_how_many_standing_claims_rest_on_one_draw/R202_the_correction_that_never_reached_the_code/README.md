# R05 · 一条只写在账本散文里的校正,不会到达仪器

`#156` 的 NEXT 指向 `#88`(18/30 对不上)。查下去发现真正的问题在 **`#90`** ——
README 头条「±22.6 / ±16.3 / ±23.7 pp」的出处。

## 先修工具:它看不见它要查的那种格式

`repro_audit` v1 的数字正则要求 **≥2 位小数**,而 `22.6` / `16.3` / `23.7` 只有 1 位。
**一个检查看不见它被造出来要检查的那种格式** —— 所以它报 `#90` "6 个数字里 5 个对不上",
而那 6 个里**根本不含**三个头条数。放宽到 ≥1 位。

## 然后:这一轮打印的,正是它自己账本判为错的那一版

`Entry 90c` 原文:

> **WRONG — the seventeenth mis-specified statistic.** 我报的是 clip 到 [0.02, 0.98] **之前**
> 的种植扰动 sd,高估 5–56%…… **校正后,交互从 ±30.8 降到 ±23.7 pp**,族的 CV 从 22.4%
> **改善**到 15.9%

**新跑输出:交互 ±30.8,CV 22.4%。** 诊断写进了账本,**代码从没改**。
`#90d` 的二项噪声校正(人层 19.8 → 16.3)同样只活在散文里,代码一直打印未校正的 20.1。

> **与 `#117e`/`#156b` 是同一个病,一轮之隔,不同声明。**
> 而这一个**更难看**:`#117` 至少是**崩溃**(退出码非零);这一个 **exit 0,静默**。

## 两条校正装进代码之后

| | 账本 | 修好后 |
|---|---:|---:|
| 人×选项交互 | **±23.7** | **±23.7** ✅ 逐位 |
| 人整体率 | ±16.3 | **±16.7**(噪声 11.2,账本记 10.4) |
| 选项基率 | **±22.6** | **±21.5** ⚠ **未解释** |

族 CV 从 22.4% 降到 **19.5%**(账本记 15.9%)。

## 剩下的那个 5%,记录不猜

`item_pp = 100·sd(列均值)` 是**确定性**的(不含随机数),而块数**仍是 23**,与账本一致。
**±22.6 → ±21.5 的 5% 漂移无法用块集变化解释。** 这正是 `repro_audit` 造出来要浮出的东西,
**记录,不用推测去解决它**。

## 声明本身站住

±21.5 vs ±23.7 —— **两者仍然一样大**,而"一样大"正是这条声明说的话。
(若说有变化,是交互现在**略大于**题目效应。)

## 一条规则

> **一条只写在账本散文里的校正,不会到达仪器。**
> 两轮之内两个实例(`#117e` 崩溃 · `#90c` 静默)。**诊断、记账、写守卫 —— 都不等于改代码。**

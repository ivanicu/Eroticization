# R212 · 三条头部声明,各自的两个分母

`#166b` 立起 **Q1**(这一次)vs **Q2**(平均)的区分。README 上的声明读起来是 Q1,
判它们时用的却几乎全是 Q2 的分母。**注册的 kill**:三条里 ≥2 条在 Q1 尺度上掉出来 → 加一列分母。

方法:**用各轮自己的代码**跨 8 个种子重跑,只加分母、不重写统计量(`#143`/`#154`)。
`#100` 的源码在 exec 时把 `__file__` 指向本轮,所以它写进本轮的 `results/`,**不覆盖 R147 的 artifact**。

## 但这一轮真正找到的是另一件事

**`#100` 的 0.432 从来没有过误差棒。** R147 的内层劈分种子是 `default_rng(700+rep)` ——
**与外层 `sd` 无关**,所以真实臂在 8 个种子上逐字节相同(`sd = 0.0000`)。
它挂着的 `−0.022` 是 **curveball 零假设的地板**,回答的是「无结构矩阵能不能造出这个数」,
**不是「这个数有多准」**。两个问题,一个数字被当成两个用。

给它两个真分母(两处文本改动改的是**驱动**,不是统计量):
- 内层种子挂到 `sd` 上 → **劈分实现展布 ±0.0081**
- 把 R147 自己算出的 `a/b/picks` 捕获出来做**人层自助(n=7,316,400 次)** → **±0.0164**

自助均值 0.4157 比已发表的 0.4320 低 **1.0 个自助 sd** —— 相关型统计量的自助偏差,方向符合预期,
不构成撤回。**正确写法:`0.432 ± 0.016`(人层自助),而不是 `0.432`(地板 −0.022)。**

## 本轮修掉的自己的错

- 第一版把 `#163` 只跑了 k=6(88.1%),而账本的 85% 是 k∈{4,5,6} 的平均。
  **不同的对象** —— `#147`/`#151`/`#161` 的 `same_scale` 家族,第四次。
- 汇总表用了列名 `mean`,与 `DataFrame.mean` 撞名。**这次 `check_columns` 被调用了,并且开火了**
  —— 就在 `#166c` 说「守卫的存在不是保护,调用才是」的下一轮。

## 但收窄过程里撞到的东西比结论大

**`+0.815` 是一条已被 `#20` 杀掉的定律,而它还挂在两份 README 上。**
`Entry 20` 的原话:*「what dies is the general claim that deficit tracks coverage across splits」* ——
K ∈ {3,5,8,12} 的中位 r = **+0.127**,最差留一 = **−0.294**(去掉 pornhabit,8 个规格中 6 个),
而 n=6 切分时置换零的 **|r| p95 = 0.820**,`+0.815` 从未越过它自己的零。
README 引的是 `#11` `#15`,**`#20` 根本没被引用**。英文版还有**第二处**未加限定的断言(行 122),
中文版没有 —— `#144d` 记过的「两套并行叙述」。**已全部改写,`#20` 现已引用。**

存活的是**校正,不是定律**:按块数匹配把 pornhabit 从 0.2285 → 0.0871 → 0.0439,
在那一个切分上直接测出来,不依赖任何相关 —— 但它**自己的精度从未被估过**,现已显式声明。

## 四个探测器 bug,全是同一类:两半用了不对称的尺

1. **前缀匹配**:`` `#15 `` 也命中 `#150`/`#151`/`#159` —— 与当初 `R\d{2}` 读到 `R204` 同形。
2. **检测跑在截断副本上**:`text=ln[:110]` 是给打印用的,而英文行更长,`9.0×` 落在 110 之后被切掉 ——
   于是**英文行被判无精度、中文行没有**。
3. **`DEAD` 正则中文有 `**反转` 英文没有 `Inverted`** —— 同一张表的两半。
4. **`PREC_INLINE` 只认 `×` 不认「倍」** —— 中文写「余量 23 倍」,被误判成无精度。

**两半用不对称的尺,是这一整轮反复犯的同一个错**(`#168e` 是它在覆盖检查上的版本)。

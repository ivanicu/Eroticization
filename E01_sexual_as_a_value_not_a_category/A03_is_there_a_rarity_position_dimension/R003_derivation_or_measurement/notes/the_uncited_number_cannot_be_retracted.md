# R04 · 一个不带出处的数字,是一个无法被撤回的数字

`#143` 的 NEXT:把 `tools/readme_ledger_audit.py` 打出的 **29 个命中**人工分诊 ——
每一个都要回答「这个数字在那一行里,是**被撤的**还是**更正后的**」。

## 分诊结果:29 个里只有 1 个是真的

| 数字 | 判定 |
|---|---|
| `0.012` `1.05` `0.135` `0.151` `0.093` `0.557` … | **良性** —— 或是巧合的子串匹配,或那个数字是撤回行里的**更正值**,或 README 已在"被撤回的"表里正确标注 |
| `0.385` | **保守方向的陈旧**:README 挂着 `#26` 的 UNVERIFIED 标记,而后来的条目说强制单选设计让那条反对**整个失效** |
| **`0.2515`** | **真的。** 账本原文:「**账本里根本没有这个数。** 它来自 A09 之前的 README 正文。`#26` 实测 **+0.2922** 未控制、**+0.2523** 加全指标,**并且把"其中 85% 是作答风格"降级为 UNVERIFIED**」 |

## 而它暴露的东西比它本身大

**README 有两套并行叙述** —— 中文表(42 行)与英文正文(116 行) —— 同一条声明在两处各写一遍:

| 事实 | 中文表 | 英文正文 |
|---|---|---|
| 色情诱导 82.7% | 行 56 ✅ 已修 | 行 131 ❌ **仍写 +0.2515 与 "85% surviving"** |
| 覆盖度定律 +0.815 | 行 87 | 行 122 |
| 三条轴 2.95 | 行 54 | 行 111 |

**`#143` 找到的是"账本的撤回没走到前页";这一轮找到的是更坏的一种 —— 走到了前页的一半。**
这是 §P16「一个事实一个家」的直接违反,代价与 `#143` 相同:读者拿到哪一份,取决于他先读到哪一段。

## 但内部一致性检查**没抓到它**,而原因就是答案

新加的 `internal_consistency()` 找到 5 个引用标记在两侧带着不同数字 —— **但行 131 不在其中**,
因为**行 131 不带任何引用标记**。

> **一个不带出处的数字,是一个无法被撤回的数字。**

`uncited_numbers()` 数了一下:README 有 **17 行带数字却不带任何出处**;去掉 Zenodo DOI 与
python 版本号,**前页有约 14 个数字没有回到账本的指针**。`#143` 的那个真错误就在这类行里 ——
**它不是被漏掉的,它是结构上不可见的。**

## 产出

- `readme_ledger_audit.py::internal_consistency()` —— 同一引用标记在两套叙述里带不同数字。
- `readme_ledger_audit.py::uncited_numbers()` —— 带数字却不带出处的行,**审计盲区的大小**。
- 行 131 已改正为账本的实测值。

# R418 · 卡片的**档数**过时,它的**删除**属实

`#373` 证明卡片与文件是两个对象。**那不等于卡片整份不可信。**
卡片有一整节 `DROPPED GT QUESTIONS`,**逐条点名**说某些列已删。
**删除是可核的**:那些列若仍在文件里,卡片就不只是过时,而是**反的**。

## 结果:0 / 13 仍在
| 组 | 标识 | 结果 |
|---|---|---|
| 人口学 | `country` · `ethnicity` · `religion_importance` · `sexage` | ✅ 确已不在 |
| 人口学 | `race` | ⚠ **仅子串命中**,不算 |
| 源列 | `attractedtomasculine` · `attractedtofeminine` · `abuse` · `sexualAssaultLevel` · `tkpfq6j` · `gjt7igv` | ✅ 确已不在 |
| 内容 | `pedophil` | ✅ 确已不在 |
| 内容 | `smost` | ⚠ **仅子串命中**,不算 |

**⇒ 卡片的删除清单,在能做的最强检验下站住了。**

## ⚠ 而第一版说「2 个仍在」—— 那两个都是**我自己匹配器**的假阳性
- `race` 命中 `Totalsexyrace` · `You find raceplay to be:` —— 那是**情色内容**,不是人口学的族裔题。
- `smost` 命中 `"I find {bodypartsmost}:"` —— 那是**引用** `bodypartsmost` 的派生题,不是那个列。

**这正是 §2 点名的 `personal`/`persona` 子串陷阱。代理账(P6):**
| | |
|---|---|
| **属性** | 该列还在文件里 |
| **代理** | 列名里出现这个子串 |
| **蕴含** | 「不出现 ⇒ 不在」**健全** · 「出现 ⇒ 在」**不健全** |
| **见证** | `Totalsexyrace` 满足代理、违反属性 |
| **安全侧** | 只用子串**证否**;出现时返回 **UNVERIFIED**,绝不判「仍在」 |

修法:加一个**整片相等**的匹配器(把列名切成标识符片段,要求整片相等),
**两个匹配器都要过同一个正对照**(8/8 已知列各自命中)。

## 对照
正对照 8/8(宽匹配器)+ 8/8(严格匹配器)· 负对照 0/4 编造标识命中。**四个门全过。**
⚠ `P5★`:「没找到」是否定断言,**正对照不是可选的,它是这一轮成立的前提**。

## IMPOSSIBLE
卡片用的是 GT 原始问题名,发布版可能**改过名** -> 「没找到」也可能是「改名了」。
**本轮只能证否(找到 = 卡片错),不能证成。** 所以措辞是「站住了」,不是「已证明」。

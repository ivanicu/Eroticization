# R220 · ② 证据缺口,有多少是我的窗口太窄造出来的

`#174` 的「结构上做不到」:限定语按**同一行**判,账本里写在下一段的看不见 → 会高估 ②。
把窗口从**行**放宽到**条目**(`## Entry N` 到下一个),重跑同一批裸数。

## 结果:② 全部消失

| 窗口 | ① 搬运缺口 | ② 证据缺口 |
|---|---:|---:|
| 行 | 24 | **12** |
| **条目** | **36** | **0** |

**公开面上每一个裸数,在账本里它自己那条条目内都有一个带限定语的家。
根本没有证据缺口 —— 全是搬运。**

## GAUGE:窗口有没有放得太宽

放宽窗口同时会放宽假阳性,所以量匹配距离:

    中位 0 行 · 90 分位 4 行 · 最大 7 行 · 距离 0(同一行)占 58% · ≤3 行占 86%

**86% 在三行之内** —— 「同一条条目」这个窗口没有把匹配拉到不相干的地方。

## 负对照失败了一次,而失败的原因值得单独记

上一轮的哨兵 `+9.9991`(选它是因为账本里不存在)**被 `#174` 的条目正文写进了账本** ——
它在被写下来的那一刻就不再"不存在"了,于是负对照判成 ①。

> **一个发表在账本里的哨兵值,就不再是缺席的。**

已改成运行时**自证缺席**:扫一批候选,取第一个在账本里查不到的。

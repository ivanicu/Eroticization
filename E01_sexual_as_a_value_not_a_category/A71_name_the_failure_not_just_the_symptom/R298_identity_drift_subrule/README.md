# R298 · 守卫 13 的身份漂移子规则:说出失败的原因,而不只是症状

**类型:CLOSURE**。

`#252c`:守卫 13 面对「被测对象在扫描中途被替换」时只会说「非单调」—— 方向对,但不够具体。
一个由**数据定义**的量(特征向量、聚类中心、主成分),种得够强时**种入本身会重新定义它**。

## 子规则
`plant_direction_from_sweep(..., identity=[...], identity_floor=0.90)`。
`identity[i]` = 第 i 个 `g` 上被测量与 `g=0` 时的**身份指纹**(1 = 同一个对象)。
**有漂移时先报漂移** —— 它比「非单调」具体得多,而且**单调也救不了它**。

## 四端自检(走独立 `Gate` 实例,`#249c` 定下的做法)
| | 情形 | 期望 | 实测 |
|---|---|---|---|
| ① | 身份稳定 + 单调 | 放行 | PASS |
| ② | 身份稳定 + 非单调 | 报「非单调」 | FAIL(正确) |
| ③ | **身份漂移 + 非单调** | 报「**对象被替换**」 | FAIL,诊断:`被测对象在 g=0.15 处被替换(指纹 1.00 → 0.20)` |
| ④ | **身份漂移 + 单调** | **也**报「对象被替换」 | FAIL,诊断同上 —— **那时的单调是假的** |

**主门只收「四端是否全对」这一条,于是它第一次是干净的**(`ALL GATES PASS`)——
`#249c` 那条做法生效了。

## ⚠ 两个我的测试用例参数错,记下来
① 第一版把**计数尺度**的灵敏度门槛(2.0)用在了**相关尺度**的扫描上(跨度只有 0.55),
于是 ① 因「灵敏度未证明」而 FAIL —— **守卫是对的,错的是我的用例。**
② 检查诊断文字时我只看了说明字段,而「对象被替换」写在明细字段里。

## 一句关于人的话(Closure 轮,没有)
产物是:守卫从「这条扫描不对劲」升级到「**这条扫描在 g=0.15 处换了被测对象**」。
**一个只报症状的诊断,会让人去修错的地方。**

# R427 · 不写更强的正则,改接口 —— 可抽取率从 **1.9%** 到 **100%**

`#382b` 的审计覆盖率只有 **1.9%**(4/212),原因是**种植幅度写在代码里的形式五花八门**。
**而「写更强的正则」是 `#374b`(`race` 命中 `Totalsexyrace`)与 `#377c`(`零` 命中 `孤零零`)
反复证明会失败的那条路。**

## ⇒ 改**接口**,不改正则
`Gate.positive_control_at_the_contested_magnitude` **在调用点记录参数**
(`self.calls` + `lib/_gate_calls.jsonl`)。
**于是审计变成「读 gate 的调用记录」,而不是「猜代码」—— 抽取按构造是精确的。**

| | R426(正则) | R427(接口) |
|---|---:|---:|
| 可抽取率 | **1.9%** | **100%** |
| 失败模式 | 子串假阳性 · 形式不统一 | 无(参数就是那两个数) |

## ⚠ 第一版把「无法比较」的调用**静默丢掉了**
坏输入与退化输入的两条路**提前 return**,没走到记录 -> 它们从审计里消失。
**而那正是 `#426` 自己刚说过的话:抽不到的不是「没问题」,是「没看」。**
> **一个丢掉自己难例的账本,会讨好它所审计的那个东西。**
修法:`_record_call` 记录**每一次**调用,带 `status`:
`COMPARABLE` · `UNCOMPARABLE_bad_input` · `UNCOMPARABLE_degenerate_contested`。

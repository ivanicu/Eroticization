# R221 · 那个"家",是不是它自己的家

`#175b` 说 100% 的裸数在账本里有一个带限定语的家。`#175c` 说清单按**串**匹配不按**所指**。
**所以 `#175b` 数的可能是「有没有一个家」,不是「有没有它自己的家」。**

**判据**:证据句**所在的条目号** ∈ README 那一行**引用的条目号集合**。

## 结果:清单可用,但四分之一要人工确认

| | |
|---|---:|
| token 总数 | 70 |
| 可判(README 行带引用标记) | **53** |
| 不可判(行不带任何引用) | 17 |
| **通过(是它自己的家)** | **39 / 53 = 73.6%** |

**73.6% ≥ 注册阈值 70% → kill 不开火,清单可以作为搬运依据** ——
但**约四分之一的配对所指不符**,必须逐条人工确认。

两个对照都钉住了方向:

- **正对照** `0.3×` → 证据在 `#120`,README 行正引 `#120` → **通过** ✅
- **负对照** `10%` → 证据在顶部表格块,README 行引的是 `#115` → **不通过** ✅

## 本轮修掉的错:第三次在截断副本上做检测

`widened.csv` 的 `line` 是**截断到 100 字符的显示副本**,而引用标记 `#NNN` 写在**行尾** ——
于是 70 个 token 里只有 **5** 个"可判",两个对照都拿不到答案(`own_home = None`),
而通过率被算成 4/5 = 80%。**一个 n=5 的 80%,和一个 n=53 的 73.6%,在纸面上长得一样。**

    第一次 `#169d`②:`text=ln[:110]`,英文行更长,`9.0×` 被切掉 -> 英文判无精度、中文没有
    第二次 `#173c` :正对照走 git 路,失败在管道 -> 差点读成"判据不成立"
    第三次 本轮      :`line[:100]`,引用标记在行尾 -> 可判样本从 53 塌到 5

**显示副本与检测输入必须是两个字段。** 已改为用截断前缀回到当前 README 的整行。

## 结构上做不到

17 行**不带任何引用标记**,这条规则判不了它们 —— 单列一类,不计入分母。
**它们才是真正没法自动搬运的那一批。**
